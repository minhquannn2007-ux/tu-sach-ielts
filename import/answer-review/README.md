# Reviewed Reading answer keys

The user now requests solutions for all published Reading lessons and post-submission grading inside the existing response table: ✅ for correct responses and ❌ with the correct answer beside incorrect or unanswered responses. This supersedes the earlier blanket no-key requirement for existing lessons. Do not fabricate solutions or enable grading on unresolved questions. Source/content approval and answer approval remain separate.

Structured practice lessons retain their source data and practice mode; complete reviewed solutions live in dist/answer-keys.json, indexed from import/answer-review/batch-*.json. Each solution pins the exact reading/question fingerprint, passage evidence and reasoning; diagram solutions additionally pin artwork hashes. The index builder rejects changed sources rather than re-certifying them. Re-review and explicitly update the pinned review record when content changes. The engine verifies the fingerprint before using a solution. Missing, invalid or stale keys leave responses ungraded. Existing graded keys remain supported. No answer table appears before submission.

IELTSGrading in exam-data.js owns scoring and result tables. Multiple-answer groups are unordered, have one credit per distinct correct choice, and display missing choices for incorrect rows. Multiple blanks are checked separately when reviewed per-slot variants exist; existing joined-answer keys still require every blank to be filled. Normalize case and whitespace only; list acceptable alternate answers explicitly. Full Test uses the same table and stores scores only for fully keyed passages, preserving completion thresholds and single submission/history. Four originally keyed HTML lessons use the same result table after their original submission logic. Other legacy pages remain pending manual solutions and integration.

Run scripts/check-reviewed-answer-keys.mjs and scripts/tests/answer-grading.mjs; run answer-grading-dom.mjs, legacy-answer-table-dom.mjs and full-test-dom.mjs with HAPPY_DOM_MODULE set. The Pages workflow also checks all reviewed answer keys. Coverage and pending lessons are tracked in import/answer-review/progress.json; never report that all lessons have solutions based on this feature alone.
